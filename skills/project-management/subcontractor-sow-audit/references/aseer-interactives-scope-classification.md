## CRITICAL — interactives are NOT screens/AV

Most interactives are PHYSICAL (blocks, mural blocks, tactile replicas, rubbing). They are NOT
Media/screen items. Confirm classification via the **Exhibit Schedule**
(`6930_Aseer_Exhibit Schedule.xlsx`), which has SEPARATE per-exhibit columns:
`Media ID` (screens/AV/projectors) · `Setworks ID` · `Model/Replica ID` · `Tactile/Manual ID` · `Graphic ID`.

- If a Media ID is absent for an exhibit, that exhibit has NO screen — its interactive
  (Tactile/Manual ID) is physical/hybrid, not AV.
- Example: ET_09.03 has Setworks + Model/Replica + Tactile/Manual, but **no Media ID** → no screen.
  Its interactive (09.03_HI_01) is hybrid and sits under the Rawasin AV/Interactive umbrella
  because of the show-control/lighting/DALI-DMX content — not because it is a screen.

## Scope ownership split (do NOT assume all interactives → Rawasin)

- **Electronic/hybrid interactives** (e.g. 09.03_HI_01 with sensors, LEDs, show-control, DALI/DMX)
  → **Rawasin** (AV/IT umbrella, T2-09; contract EXECUTED). The only interactive requiring
  hardware/firmware/show-control.
- **Physical/manual/tactile interactives** (building blocks, mural blocks, tactile replicas,
  rubbing) → **Replicas/Models + Setworks**, NOT Rawasin. Rawasin is AV/IT; a building-block
  interactive is not AV.
- **Replicas/Models** (crowns 09.03_RE_01, herbs 09.03_RE_02, 05.02_RE_01 30x TBC, 12.05_RE_01/02)
  → Replica/Models subcontractor (BOQ Sec 010 Models & Replicas). Interactive specialist only
  **integrates** the mounting — it never fabricates replicas/glass/joinery.
- **Glass cases, counter, patinated-brass label housing, timber/joinery/metalwork**
  → glass workshop + setworks. Not the interactive specialist.

## SOW pitfalls (editing INT-001 for CG submission)

- The SOW was framed as an RFP ("invites specialist proposals", full Prequalification section 4).
  For submission to CG as a scope statement, remove the prequalification/RFP framing — the
  interactive is Rawasin (sister co, contract EXECUTED), not an open tender. Deleting the
  prequalification section + switching "invites proposals" → "defines the scope" avoids the
  submission looking like a tender.
- Keep technical sections: exhibit context, components, scope of work, key parameters,
  programme milestones, NRS RFI questions, quality, interfaces, BOQ refs.
- Remove internal-only obligations (e.g. "forward to CG via 72h DIR cycle") and any internal
  decision commentary when presenting to CG.
- Add an explicit **SCOPE BOUNDARY** note when the interactive specialist does NOT fabricate
  the physical exhibits: it only integrates onto items supplied by others (counter, glass,
  replicas, joinery).

## Evidence-before-answer rule (user correction)
When the user asks "is this scope complete / does this cover X", verify against the ACTUAL
schedules (Tactile/Manual, Model & Replica, Exhibit) before answering. The repo READMEs
(`03_Scope/scope_summary.md`, `INTERACTIVE_UNDERSTANDING_REPORT.md`) only LIST the schedules or
summarise one exhibit — they do not capture all 6 interactives. Never assert completeness from
the summary; read the xlsx/PDF.
