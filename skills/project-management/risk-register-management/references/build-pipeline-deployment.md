# Register Build Pipeline & Deployment

## Multi-register architecture

Each register has its own source data and build script:

| Register | Source | Build script | Output |
|----------|--------|--------------|--------|
| PRR | `06_Risk_System/risks.json` | `webapp/build_risk.py` | `webapp/src/index.html` |
| DDR | `06_Risk_System/generated/drr_risks.json` | `webapp/build_ddr.py` | `webapp/src/DDR/index.html` |
| HSE | `06_Risk_System/generated/hse_risks.json` | `webapp/build_hse.py` | `webapp/src/HSE/index.html` |
| AVR | `webapp/av/risks_av.json` | `webapp/av/build_av.py` | `webapp/av/src/index.html` |

All builds use `webapp/template.html` as the common template, injecting data via `__RISK_DATA__` token.

## fix_cards_static.py post-processor

**Location**: `06_Risk_System/webapp/fix_cards_static.py`

The template has 4 static register cards (PRR/DDR/HSE/AVR) with PRR always marked `reg-current`. This script runs after each build and rewrites the cards so the correct register shows as current. It uses nesting-aware HTML parsing (counts `<div>` depth) rather than regex.

Each build script calls it:
```python
if __name__ == "__main__":
    ret = main()
    spath = HERE / "fix_cards_static.py"
    if spath.exists():
        subprocess.run([sys.executable, str(spath), str(OUT)], check=False)
    raise SystemExit(ret)
```

**DO NOT** add JS functions to `template.html` for card fixing — this caused the entire page to fail silently (syntax error from ES6 template literals prevented script block from parsing).

## Build script pitfalls

### `Path` vs `pathlib.Path` import error
When adding post-processing code to build scripts, use `pathlib.Path` (already imported), not bare `Path`:
```python
# WRONG — NameError: name 'Path' is not defined
spath = Path(__file__).resolve().parent / "fix_cards_static.py"

# RIGHT — uses existing import
spath = HERE / "fix_cards_static.py"
# or
spath = pathlib.Path(__file__).resolve().parent / "fix_cards_static.py"
```

### `_build_xlsx()` call must use keyword arguments
The `build()` function in `build_xlsx.py` uses keyword-only params (after `*`). Pass all args by name:
```python
# WRONG — TypeError: build() takes 2 positional arguments but 5 were given
_build_xlsx(data, str(xlsx_path), page_url=..., ...)

# RIGHT
_build_xlsx(data, out_path=str(xlsx_path), page_url=..., ...)
```

### AVR build script location
`build_av.py` lives in `webapp/av/` (not the main `webapp/` dir). Run from its own directory:
```bash
cd 06_Risk_System/webapp/av && python3 build_av.py
```

### `risks.json` contamination after git pull
`06_Risk_System/risks.json` should contain only PRR risks (61). But merge conflicts and auto-sync frequently add DDR/HSE/AVR risks. Check after every git pull:
```bash
python3 -c "
from collections import Counter
import json
with open('06_Risk_System/risks.json') as f: d = json.load(f)
print(Counter(r['id'].split('-')[0] for r in d['risks']))
"
# Should output: Counter({'PRR': 61})
```

## Excel snapshot generation

All snapshots are generated by `build_snapshots.py --bump` (increments counter, builds fresh):
```bash
cd 06_Risk_System/webapp && python3 build_snapshots.py --bump
```

This generates snapshots for **PRR, DDR, HSE** but NOT AVR. AVR snapshots are generated by `build_av.py`:
```bash
cd 06_Risk_System/webapp/av && python3 build_av.py
```

### Excel column customisation
See `references/excel-snapshot-columns.md` for the full column layout. The `REG_COLS` array in `build_xlsx.py` defines Risk Register sheet columns. To remove or add a column, update both `REG_COLS` and the `vals` array in `build_xlsx.py` in sync.

### Snapshot deployment
New snapshots must be SCP'd to the server AND old snapshots cleaned up (the build script picks the alphabetically-last file, so stale old snapshots with higher sequence numbers take precedence):
```bash
# Remove old
ssh -p 65002 server "rm -f /remote/path/OLD-FILE.xlsx"
# Deploy new
scp -P 65002 file.xlsx server:/remote/path/
# Rebuild webapp so DOWNLOAD SNAPSHOT links point to new file
python3 build_risk.py && scp src/index.html server:...
```

## Auto-deploy cron

A Hermes cron job `deploy-registers-on-commit` runs every 15 minutes. It checks the repo for changes, builds all registers, and deploys. **SCP'd files are overwritten within 15 min.** Always commit+push and let the cron deploy.

The manual auto-sync (`update-all-registers.sh`) only covers PRR and LN. The 15-min cron covers all registers.

## Deploy verification

Always verify the server has the correct file by comparing hashes:

```bash
ssh -p 65002 u517606786@samaya-factory.com "md5sum /remote/path/index.html" | awk '{print $1}'
md5 -q local/path/index.html
# Must match
```
