# Design Recovery Plan Case — ZD-0104 (Aseer, Aug 2026)

Worked example of a CG Code D rejection on a recovery plan because its forecast finish dates exceeded the contractual completion date, and the subsequent re-request.

## Context
- Contract 0010003521 — Rehabilitate and equip museum displays, Aseer. Original programme 01-Dec-2025 to 30-Sep-2026.
- Design phase completion target: 30-Sep-2026.
- Separate EOT: LT-0007 (223 days, 30-Sep-2026 → 11-May-2027), signed by GM Alajmi, pending with MoC (Eng. Al-Arjani) the whole time. References LT-0027 (03-Aug) and LT-0028 (10-Aug).

## CG Code D rejection — ZD-0104 (04-Aug)
- Submittal: MOC-MUS-ASE-1K0-ZD-0104 "Design Phases Recovery Plan", submitted 03-Aug by Hesham, via Aconex (WF-000200).
- CG response (Hossam Mabrouk, 04-Aug): **D — Rejected**.
- Verbatim CG comment: *"The design phase forecast finish dates exceed the contractual completion date. The submitted schedule is therefore disapproved."*
- Root cause: the rejected plan had 90% Technical Design finishing 01-Oct and IFC 100% package 14-Oct — both PAST the 30-Sep contractual date. CG would not accept a recovery plan that extended past the deadline.

## Key lessons
1. CG explicitly distinguishes a **recovery plan** (must stay inside the contractual completion date) from a **revised schedule** (may push dates, usually tied to EOT). CG says "Not a revised schedule" when it wants the recovery plan.
2. A recovery plan whose forecast finish dates exceed the contractual date gets **Code D**, not Code C. It is a full re-submission, not a revision.
3. The EOT (223 days) is a separate, pending claim. CG will NOT wait for it. The recovery plan must show recovery within the original deadline, with the EOT noted only as a contingency track.
4. Every interim milestone in the re-submitted plan must fit inside 30-Sep-2026.
5. Submit only after every designer/specialist has confirmed (in writing) their commitment to the compressed dates + additional resources/overtime.
