# CG Comments on SOW/Scope Documents vs Technical Submittals

When CG returns **Code C (Revise and Resubmit)** on a **Scope of Work** document, the
nature of the comments differs fundamentally from a technical submittal (drawings,
calculations, material submittals). Handle them differently.

## The core distinction

- **SOW / Scope document** = defines *what* is required (activities, responsibilities,
  interfaces, integration). It is the basis for **hiring/appointing** the specialist.
- **Technical submittal** (drawings, calcs, MAR, method statement) = the *deliverable*
  itself, produced by an already-appointed specialist.

CG sometimes conflates the two and demands **personnel CVs / org structure / named
specialists** on a SOW. That is **premature**: you cannot submit a CV for a person who
is not yet appointed, and the SOW is precisely the document that lets you hire them.

## Response strategy (SOW Code C)

1. **Accept the scope-related comments** — responsibility matrix, interface definition,
   local (KSA) execution/support plan, third-party prequalification applicability.
   These legitimately belong in the SOW and should be revised in.
2. **Defer the personnel comments** — CVs, org structure, named specialist, demonstrated
   experience. Reply: these follow SOW approval; once the SOW is approved we appoint the
   qualified specialist and submit their CV/qualifications for approval per the contract
   (e.g. Section 5.5). Do not invent a CV for an unappointed person.
3. **Frame it as stage-appropriate** — "the SOW defines the scope; appointment and
   personnel approval is the next stage after SOW acceptance." This is a legitimate
   sequencing argument, not an evasion.

## Worked example (Aseer Museum, Sep 2026)

CG returned **Code C** on `MOC-MUS-ASE-1E0-ZD-0113` Interactive Design Specialist SOW
(Rawasin). 5 comments:
1. Appoint qualified Specialist Exhibition Staff (incl. Mechanical/Electromechanical
   Interactives Specialist) + submit org structure, CVs, qualifications — **premature**.
2. Identify third-party specialist role + prequalification applicability — **scope**.
3. Revise responsibility matrix (Interactive Design / Rawasin AV / Setworks-Joinery /
   supporting specialist) — **scope**.
4. Provide KSA local execution & support arrangement — **scope**.
5. Confirm Samaya/Information Network Specialist accountability — **scope**.

Key point: CG **noted Rawasin as responsible for Interactive Design** — it did NOT reject
Rawasin. Code C ≠ rejection (that's Code D). The SOW content itself was not rejected;
only the missing responsibility/interface detail and the premature personnel demand.

## Pitfalls

- **Don't read Code C as rejection of the specialist.** Code C = revise & resubmit;
  Code D = rejected. CG explicitly "noted" Rawasin's role — that's acceptance of the
  arrangement, not a rejection.
- **Don't fabricate a CV/org chart** to satisfy a premature comment. Defer it with the
  stage-sequencing argument.
- **Separate the two comment classes** in the reply: "we will revise the SOW to address
  scope/interface comments; personnel approval follows SOW acceptance."
